# 列表分页统一设计（方案 A）

> 日期：2026-08-09 · 状态：设计已批准（用户确认）· 范围：`/user/page` 参数对齐 + authStatus DB 级过滤 + RealNameAudit/UserList 前端真分页

## 一、背景与目标

现状盘点：
- **后端**：11 个列表接口中 10 个已统一为 `pageNum/pageSize` 分页参数 + `PageResult{total, records}` 响应。**唯一不一致**：`GET /user/page` 用 `page`/`size`，且**无 `authStatus` 过滤参数**（导致实名审核页只能全量拉取后客户端过滤）。`getUserByPage` 逐行 `usersInfoMapper.selectById` 联查 usersinfo，存在 N+1。
- **前端**：15 个列表页已用 `el-pagination`；**只有 RealNameAudit 全量加载（`size:200`）+ 客户端过滤**。`getUserList` 两个调用方（`UserList.vue`、`RealNameAudit.vue`）均传 `page`/`size`。

目标（方案 A，用户选定）：
1. `/user/page` 分页参数对齐为 `pageNum/pageSize`。
2. 新增 `authStatus` DB 级过滤（JOIN usersinfo，顺带消除 N+1）。
3. RealNameAudit 改服务端分页，UserList 分页参数对齐。

## 二、后端改造

### 2.1 Controller：`UsersController.getUserInfoByPage`（`/user/page`）

参数（全部为 query 参数）：
- `pageNum`（默认 1，替换原 `page`）
- `pageSize`（默认 10，替换原 `size`）
- `username`（可选，LIKE）
- `email`（可选，LIKE）
- `isActive`（可选，TRUE/FALSE）
- `authStatus`（**新增**，可选，接收中文值：`认证中`/`认证通过`/`认证失败`/`未认证`，与响应 `@JsonValue` 描述一致，前端可直接传 tab 值）

返回：`Result<PageResult<UserPageVO>>`（结构不变）。

### 2.2 Mapper：JOIN 分页查询 + count

新增（XML 或注解）两个方法：
- `selectUserPageWithInfo(UsersConfig)`：`users u LEFT JOIN usersinfo ui ON ui.UserID = u.UserID`，按 username/email/isActive/authStatus 过滤，`ORDER BY u.UserID` + `LIMIT` 分页。
- `countUserPageWithInfo(UsersConfig)`：同条件 count。

authStatus 过滤语义：
- `认证中`/`认证通过`/`认证失败` → `ui.auth_status = <对应 AuthenticationStatus.dbValue 整数>`
- `未认证` → `ui.UserID IS NULL`（无实名记录）
- 不传 → 不过滤（=全部）

JOIN 一次取回 usersinfo 字段（auth_status/auth_level/identity_no/name/user_role/role_img_src/certifie_time），替代当前逐行 `selectById`，消除 N+1。

### 2.3 DTO：`UsersConfig`

- `page`/`size` → `pageNum`/`pageSize`
- 新增 `authStatus`（String，中文值）

### 2.4 Service：`UsersServiceImpl.getUserByPage`

改用 JOIN 查询结果组装 `UserPageVO`（authStatus 无记录时取 `UNAUTHORIZED`、authLevel 0，逻辑保持现有一致）。

## 三、前端改造

### 3.1 `web/src/api/index.js getUserList`

签名不变（`(listSelectCondition) => http.get('/user/page', { params: listSelectCondition })`），透传参数。

### 3.2 `UserList.vue`

- `userInfoConfig`：`page/size` → `pageNum/pageSize`
- `el-pagination`：`:current-page="userInfoConfig.pageNum"`、`:page-size="userInfoConfig.pageSize"`、`handleSizeChange/handleCurrentChange` 同步改

### 3.3 `RealNameAudit.vue`

- 查询改服务端：`getUserList({ pageNum, pageSize, authStatus: activeTab === 'ALL' ? undefined : activeTab })`
- 删除 `size:200` 全量加载与 `filteredList` 客户端过滤，改用后端返回 `records` + `total`
- 新增状态：`pageNum`（默认 1）、`pageSize`（默认 10）、`total`；切 tab 重置 `pageNum=1` 并 `loadData`
- 底部加 `el-pagination`（`total`、`current-page`、`page-size`、`@current-change`/`@size-change`）
- 统计卡计数：`loadData` 时对 认证中/认证通过/认证失败/全部 各用 `pageSize=1` 轻量查询读 `total` 填充
- 操作按钮逻辑不变（按行 `authStatus === '认证中'` 显示通过/驳回）

## 四、契约变更（破坏性）

- `GET /user/page` 参数 `page`/`size` → `pageNum`/`pageSize`：
  - 验证器 **TC-015 `user_page_query`** 当前用 `?page=1&size=5`，需改 `?pageNum=1&pageSize=5`
  - 先前造待审用户的核对脚本（`?page=1&size=200&username=pending_audit`）同步更新
- 新增 `authStatus` 参数；`/user/page` OpenAPI 契约需刷新
- 前端两个调用方（UserList、RealNameAudit）随本次同步改，无遗留
