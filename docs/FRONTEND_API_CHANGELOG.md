# 前端对接升级文档

本文档详细描述了后端针对委托全流程（创建、审核、发布、接收、进度更新、完成）所进行的接口升级和数据模型变更。请前端同学根据本文档进行相应的适配和开发。

## 0. 最新迭代（2026-08-09）

### 0.1 变更：系统公告日期字段序列化统一为时间戳

系统公告相关接口（公告列表/详情/首页最新公告）响应中 `publishTime`、`startEffectiveTime`、`endEffectiveTime` 由字符串（原 `"2026年08月05日01:55:00"`）改为 **epoch 毫秒时间戳**，与 `createdAt`/`updatedAt` 一致。

**适配**：列表直接用 `| dateTime` 过滤器格式化；新增/编辑提交时日期字段传 Date 对象（JSON 序列化为 ISO 字符串）即可，后端默认反序列化。

## 0. 最新迭代（2026-07-31）

### 0.1 新增：履约节点标准化打卡

新增 `POST /taskUpdate/node`，接收者按**固定三节点**（已联系 / 已取件 / 已送达）打卡，支持上传打卡图片、定位、备注。

**请求体示例 (JSON)**:

```json
{
  "taskId": 10086,
  "nodeType": "CONTACTED",   // CONTACTED / PICKED_UP / DELIVERED
  "imgUrl": "http://domain/photos/xxx.png",
  "location": "120.1124,30.2994",
  "remark": "已联系发布者，确认取件时间"
}
```

- 仅任务状态为 `ACCEPTED` 且为接收者本人可提交。
- 原有 `PROGRESS_UPDATE` 自由文本进度**保留用于兼容历史数据，不再作为主推流程**。

### 0.2 移除：邮箱激活接口

`GET /user/active/{id}` 邮箱激活接口**永久下线**。注册后用户直接登录，无需邮箱验证。

### 0.3 新增：定时任务

新增**已完成委托 24h 自动评价**定时扫描：任务完成超过 `app.auto-review.delay-hours`（默认 24 小时）且无人工评价时，系统自动生成中性好评（3 星，标注「系统自动评价」）。

## 1. 变更概览

| 变更类型 | 描述 | 涉及模块 |
| :--- | :--- | :--- |
| **新增字段** | 委托任务增加 `money` (金额) 字段 | 创建委托, 委托详情 |
| **新增接口** | `PUT /task/auditTask/{id}` | 提交审核 |
| **新增接口** | `POST /taskUpdate/add` | 任务进度更新（自由文本，历史兼容） |
| **新增接口** | `POST /taskUpdate/node` | 履约节点打卡（已联系/已取件/已送达） |

| **枚举新增** | `TaskUpdateType` 新增 `PROGRESS_UPDATE` (进度更新) | 任务动态/日志 |

## 2. 数据模型变更

### 2.1 Task (委托任务)

在 `Task` 实体及相关 DTO 中增加了 `money` 字段。

*   **字段名**: `money`
*   **类型**: `BigDecimal` (数字)
*   **说明**: 委托金额/报酬
*   **适用范围**: 
    *   创建委托 (`TaskDTO`)
    *   委托详情展示 (`Task`, `TaskDraftVO`, `TaskDetails` 等返回体中已包含)

## 3. 接口变更详情

### 3.1 创建委托 (修改)

**接口**: `POST /task/addTaskDraft`

**变更**: 请求体 `TaskDTO` 增加 `money` 字段。

**请求体示例 (JSON)**:

```json
{
  "taskId": 0,          //如果是修改草稿则传ID，新增传0或不传
  "ownerId": 123,
  "location": "图书馆",
  "content": "帮我借本书",
  "type": "跑腿",
  "money": 15.50        // [新增] 委托金额
}
```

### 3.2 提交审核 (新增)

用户创建草稿后，需调用此接口将任务状态从 `DRAFT` (草稿) 变更为 `AUDITING` (审核中)。

*   **URL**: `/task/auditTask/{id}`
*   **Method**: `PUT`
*   **Path Parameters**:
    *   `id` (Long): 委托任务 ID
*   **Response**:
    *   `200 OK`: `{"code": 200, "msg": "操作成功", "data": null}`

**前端逻辑建议**:
在“我的草稿”列表或详情页，增加“提交审核”按钮。点击后调用此接口。

### 3.3 添加任务进度更新 (新增)

接收者（Receiver）在任务执行过程中（状态为 `ACCEPTED`），可以提交任务进度（如“已到达目的地”、“正在排队”等）。

*   **URL**: `/taskUpdate/add`
*   **Method**: `POST`
*   **Content-Type**: `application/json`
*   **Request Body**: `TaskUpdateDTO`

**请求体示例 (JSON)**:

```json
{
  "taskId": 10086,
  "description": "我已经到达取件点，正在排队。"
}
```

*   **Response**:
    *   `200 OK`: `{"code": 200, "msg": "操作成功", "data": null}`

**前端逻辑建议**:
在“我接收的任务”详情页，增加“更新进度”或“添加留言”功能。用户输入文字后调用此接口。

## 4. 枚举变更

### 4.1 TaskUpdateType (任务更新类型)

在 `TaskUpdateType` 枚举中新增了类型，用于标识任务进度的更新记录。

| 枚举名 | Code | Web Value | 说明 |
| :--- | :--- | :--- | :--- |
| `PROGRESS_UPDATE` | `5` | `"进度更新"` | 接收者提交的自由文本进度（**历史兼容**，不再主推） |
| `CONTACTED` | `6` | `"已联系"` | 履约节点：已联系发布者 |
| `PICKED_UP` | `7` | `"已取件"` | 履约节点：已取件 |
| `DELIVERED` | `8` | `"已送达"` | 履约节点：已送达 |

**前端逻辑建议**:
在展示任务动态/时间轴（Task Timeline）时，遇到 `CONTACTED / PICKED_UP / DELIVERED` 的记录按**结构化节点卡片**展示（图标 + 节点名 + 图片 + 定位）；遇到 `PROGRESS_UPDATE` 的记录按普通文本进度展示（历史兼容）。

## 5. 完整业务流程示例

1.  **发布者**创建任务 (`POST /task/addTaskDraft`)，填写金额 `money`。 -> 状态 `DRAFT`
2.  **发布者**提交审核 (`PUT /task/auditTask/{id}`)。 -> 状态 `AUDITING`
3.  **管理员**审核通过 (原有接口)。 -> 状态 `PENDING_RELEASE`
4.  **发布者**确认发布 (原有接口)。 -> 状态 `ONGOING`
5.  **接收者**申请接收 (原有接口)。
6.  **发布者**确认接收人 (原有接口)。 -> 状态 `ACCEPTED`
7.  **接收者**履约节点打卡 (`POST /taskUpdate/node`)，按 **已联系 → 已取件 → 已送达** 提交（支持图片/定位/备注）。 -> 插入结构化 `TaskUpdates` 记录
8.  **接收者**完成任务/发布者确认完成 (原有接口)。 -> 状态 `COMPLETED`
9.  （自动）任务完成超过 24 小时且无人工评价，系统自动生成中性 3 星评价。

## 6. 常见问题 (FAQ) & 注意事项

1. **金额字段格式**：
   - 提交 `money` 时请注意数据类型为数值型（例如 `15.50`），前端输入框建议限制为最多两位小数。
2. **任务状态扭转控制**：
   - 只有 `DRAFT` 状态的任务才可以调用 `提交审核` 接口，否则后端将返回状态异常的错误提示。
   - 只有 `ACCEPTED` 状态的任务，接收者才能调用 `履约节点打卡`（`POST /taskUpdate/node`）或历史兼容的 `添加任务进度更新` 接口。
3. **老数据兼容**：
   - 历史任务数据中可能没有 `money` 字段（或者为 `null` / `0`），前端在展示时请做好判空和默认值处理。
   - 历史 `PROGRESS_UPDATE` 自由文本进度记录保留，前端按普通文本展示即可。
4. **注册流程**：
   - 注册后直接登录，**无需邮箱激活**；`GET /user/active/{id}` 已下线，前端不要依赖激活链接。
5. **前端UI提示**：
   - 提交审核和履约节点打卡时，建议在请求发起期间增加 Loading 动画，防止用户重复点击提交。
